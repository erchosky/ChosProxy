# ADR-0030: HTTP/2 in the Request Engine and the single-packet attack

* Status: Accepted
* Date: 2026-11-12

## Context
The parity matrix asks for HTTP/2 end to end (PROXY-020), HTTP/2 editing in
Repeater (REPEATER-006) and the HTTP/2 single-packet attack for race
conditions (REPEATER-003). Every viewer, the history, the Inspector,
passive analysis and the Fuzzer work on messages as text (ADR-0009). That
should stay true for HTTP/2.

## Decisions
1. **HTTP/2 messages keep the text form.**
   * A request is HTTP/2 when its request line ends with `HTTP/2`.
   * Responses are stored as `HTTP/2 <status>`, then the header fields with
     lower-case names, then the body joined from its DATA frames.
   * The head parser recognises the `HTTP/2` token (`Version::Http2`).
     Everything that reads heads keeps working unchanged.
2. **Translation to frames.**
   * `:method` and `:path` come from the request line; `:authority` comes
     from `Host` (or the destination); `:scheme` comes from the connection.
   * Header names are lower-cased.
   * Connection-specific headers (`Connection`, `Keep-Alive`,
     `Proxy-Connection`, `Transfer-Encoding`, `Upgrade`, and `TE` other
     than `trailers`) are dropped with a note in the history.
   * A chunked body is sent as plain DATA.
3. **One switch for every tool.**
   * `chosproxy_request::send` sends HTTP/2 requests with the `h2` crate on
     a new connection: TLS must agree on `h2` through ALPN, and plain
     connections use h2c with prior knowledge.
   * Upstream proxies, host overrides and timeouts (ADR-0029) apply.
   * Repeater, the Fuzzer, the Sequencer and the crawler therefore speak
     HTTP/2 whenever the request says so.
   * Kept connections are HTTP/1.1 only, so HTTP/2 requests always get
     their own connection.
4. **Single-packet attack.**
   * A parallel Repeater group whose tabs are all HTTP/2 to the same
     destination (at most 50) shares one connection.
   * Each request is sent without its final frame (the last body byte, or
     an empty DATA frame ending the stream).
   * Writes are then held behind a gate below the HTTP/2 layer. The final
     frames of all requests are queued, the gate opens, and a PING makes
     the connection write everything in one call. Small final frames then
     reach the server in one TCP packet.
   * It is best effort: the operating system decides the segments. Final
     frames that do not fit one packet still arrive together.
5. **Importing a CA.**
   * Proxy → HTTPS accepts a CA certificate and its unencrypted PKCS#8 key.
   * The import is refused unless the certificate is a CA, has not expired
     and matches the key.
   * The previous CA is kept as `*.previous.pem`, with private permissions.

## Consequences
* HTTP/2 needs no change in storage, viewers or analysis.
* Requests that are not valid HTTP/2 (CR/LF in values, raw or duplicate
  pseudo-headers) cannot be sent, because the `h2` crate validates them.
  Raw frames come later.
* Deferred, explicitly, to **M21c**:
  * HTTP/2 between browsers, the proxy and servers (the proxy still
    negotiates HTTP/1.1 on both sides);
  * raw or invalid HTTP/2;
  * per-listener TLS options, a fixed "redirect to host" for invisible
    listeners, and port/regex passthrough rules;
  * OAST SMTP and ACME certificates.
