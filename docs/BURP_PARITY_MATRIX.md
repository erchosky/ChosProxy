# Capability Parity Matrix (reference: Burp Suite Professional)

Inventory of the capabilities of the reference professional suite and the
ChosProxy equivalent for each. ChosProxy implements every capability with
its own engineering, UI and naming (see
[PROJECT_SPEC_ADDENDUM_PARITY.md](PROJECT_SPEC_ADDENDUM_PARITY.md)).

* Reference snapshot: public product documentation and release notes up to
  release 2026.10 (October 2026). Re-verify in **M32** (parity audit) and
  whenever the reference changes.
* A row only counts as 🟢 under the parity rule (spec §127): real work, real
  traffic, integrated, persisted, error-handled, tested, documented, scoped,
  resource-pool aware, safe.
* `Test ID` refers to the parity suite in [`tests/parity/`](../tests/parity/).

Legend: ⬜ not implemented · 🔵 planned (milestone assigned) · 🟡 partial ·
🟢 feature complete · ⭐ superset · ➖ not applicable (justified)

Every row names its ChosProxy equivalent. Rows that are not built say so and say why: waiting for a separate design decision (such as runtime instrumentation or extension editor tabs).

Parity is **not** declared. The M32 audit (docs/audits/2026-11-14-m32-parity-audit.md) checked every row against the code and the tests: 87 rows complete, 41 partial, 4 not built, 2 not applicable. M33 closed seven small gaps (94 / 34 / 4 / 2), and completing M31 (steps A, C, F) plus M13 (Active Audit Framework) brought the matrix to 100 complete, 30 partial, 2 planned (needs decision), and 2 not applicable. The remaining partial/planned rows are documented below and in ADR-0044.
