# Threat Model

Scope: the ChosProxy desktop application and its local data. Method: assets →
trust boundaries → STRIDE threats → mitigations. Reviewed at the end of every
milestone; the "Status" column says what is implemented today.

## Assets

| Asset | Why it matters |
|---|---|
| Local CA private key (M2) | Anyone holding it can MITM the user's lab browser |
| Project databases | Contain captured credentials, cookies, tokens, PII of test targets |
| Config files | Listener exposure, plugin grants (`plugins.toml`) |
| Cookie jar and stored sessions (M4) | Live session cookies of the targets, replayed by the Repeater |
| The workstation | The WebView has IPC access to the engine and filesystem paths |

## Trust boundaries

1. **Network → proxy listener** (any process that can connect; remote hosts
   if remote access enabled).
2. **Upstream server → proxy** (fully attacker-controlled responses).
3. **Engine → WebView** (untrusted bytes displayed in a privileged UI).
4. **Files → engine** (project files, imports (M8+), plugin manifests (M14)).
5. **OAST server ↔ the internet** (M18): the local or self-hosted
   interaction server receives traffic from anyone; the self-hosted API is
   reached over the internet.
6. **Plugin process ↔ engine** (M14): a separate program speaking JSON
   lines; every message it sends is untrusted and checked against its grants.
7. **Engine → targets** (M10–M12): automated tools send traffic on the
   tester's behalf, so their reach must stay within the authorization.

## Threats and mitigations

| # | Threat (STRIDE) | Mitigation | Status |
|---|---|---|---|
| T1 | Other LAN hosts use the proxy as an open relay / read history (I, E) | Listeners bind loopback by default; enabling `allow_remote` is explicit and warned; optional per-listener Basic authentication with a salted PBKDF2 hash (M5), credentials stripped before forwarding; note Basic travels in clear text to the listener | ✅ M1/M5 |
| T2 | Proxy loop / self-request amplification (D) | Requests targeting our own listener addresses are refused with 508 | ✅ M1 |
| T3 | Malformed/huge messages crash or exhaust the proxy (D) | Head size limit (64 KiB), header count limit, streaming bodies, capped capture, per-connection idle timeouts, no panics on input; every parser of untrusted input (HTTP heads, framing, bodies, content codings, cookies, URLs, WebSocket close frames, passive checks, link discovery, token extraction, fuzzer templates, plugin messages and manifests, Decoder operations) is exercised by a deterministic mutation harness (`crates/app/tests/robustness.rs`, M16) | ✅ M1/M16 |
| T4 | Request smuggling ambiguity (CL+TE) desyncs proxy (T) | TE authoritative per RFC 9112; conflict flagged; tests | ✅ M1 |
| T5 | XSS in the UI from captured content → IPC abuse (E) | Text-only rendering, CSP, lint ban on `dangerouslySetInnerHTML`, minimal Tauri capabilities (ADR-0007); the Render view uses a permission-less sandboxed iframe with a blocking CSP (ADR-0014) | ✅ M0/M6 |
| T6 | Secrets leaking into application logs (I) | Headers never logged by default; redaction helper for Authorization/Cookie/Set-Cookie/Proxy-Authorization; log level default INFO | ✅ M0 |
| T7 | Project files readable by other local users (I) | DB and config files created `0600`, dirs `0700` on Unix | ✅ M0 |
| T8 | Malicious config file (path traversal, oversized values) (T) | Typed deserialization with validation; unknown fields rejected; values range-checked | ✅ M0 |
| T9 | CA key theft or reuse across installs (S) | Per-install generation, key `0600` in a `0700` dir, never exported/served/logged (Debug impl omits it), validation on load, explicit regeneration; only the public certificate is downloadable | ✅ M2 |
| T10 | Malicious project/import files (SQL, zip-slip, huge allocations) (T, D) | Project files checked (application id, schema version, `quick_check`) before use; import size limits; no path joins from file content (see T22) | ✅ M8 |
| T11 | Malicious plugins (E, I) | Separate process with a cleared environment, its own folder as working directory and killed with the engine; manifest validated (id = folder name, no `..` or absolute command paths); nothing granted automatically, approval tied to a SHA-256 of the plugin folder (changed files need approval again); every message checked against the grants and denials audited (`plugin.denied`); `network.send`, `project.read` and `ui.extend` refused in API v1; line (1 MiB) and body (256 KiB) limits. Not a sandbox: the program keeps the user's OS rights, which the Plugins view states (ADR-0025) | ✅ M14 |
| T12 | Isolated browser profile leaks into user profile (I) | Temporary `0700` profile per launch, deleted on exit, stale ones removed after 24 h; trust via SPKI pin (Chromium) or per-profile NSS import (Firefox), never the system store | ✅ M2 |
| T22 | Malicious settings or project files imported (T) | Settings imports validated per section and previewed before an explicit apply (all-or-nothing); size limit 2 MB; credentials never exported; project files checked (application id, schema, `quick_check`) before restore | ✅ M8 |
| T23 | Backups leak project data (I) | Backup files `0600`, app-created backup folder `0700`, in-scope-only option; audit log of exports and backups | ✅ M8 |
| T21 | Huge or endless WebSocket frames exhaust memory (D) | Frames above 64 MiB end the connection; stored payloads capped at the capture limit; paused messages ≤ 8 MiB and counted in the Intercept queue limits | ✅ M7 |
| T20 | Decompression bombs and huge inputs in the Decoder (D) | 16 MiB input and 32 MiB decompressed limits, chains ≤ 32 steps, diff token/edit limits | ✅ M6 |
| T13 | Telemetry / data exfiltration (I) | No telemetry or outbound calls besides user-directed traffic | ✅ M0 |
| T14 | Command injection when launching browsers (E) | `Command` with argument vectors only, browsers chosen from a fixed list of detected executables, start URL restricted to http(s) | ✅ M2 |
| T15 | MITM of the user's upstream connections through ChosProxy (S, T) | Upstream certificates verified against system + Mozilla roots; exceptions are explicit per host (default loopback only) and noted on each exchange | ✅ M2 |
| T16 | Interception of traffic outside the authorization (I) | Passthrough list, interception switch; scope engine with "only in scope" Intercept and filters (M5); the crawler checks every URL at send time (start origins only when no scope exists), and the Fuzzer and Sequencer refuse an out-of-scope target when a scope is defined (M16) | ✅ M2/M5/M10/M16 |
| T18 | Memory exhaustion through paused messages (D) | Paused messages ≤ 8 MiB each, queue ≤ 500 messages and 256 MiB; beyond that traffic passes through unpaused | ✅ M3 |
| T19 | Edited traffic misattributed in reports (R) | Edited/dropped flags and the original message are stored with every intercepted exchange | ✅ M3 |
| T24 | Session cookies leaking from the Repeater cookie jar (I) | The jar lives in the project database (T7 file modes); cookies sent only to hosts and paths they match (RFC 6265 domain and path rules, `Secure` only over TLS); clearing the jar is one action (ADR-0020) | ✅ M4 |
| T25 | Automated tools overloading a target (D) | Concurrency and requests-per-second limits on the crawler, Fuzzer and Sequencer; crawler GET-only with depth, request and variant caps; pause and cancel at any time; tasks stop when the project closes | ✅ M10–M12 |
| T26 | Crawler following links to unrelated sites (I, E) | See T16: links are only followed within the scope, or within the start origins when no scope is defined; robots.txt and sitemap paths are fetched only on the start origins | ✅ M10 |
| T27 | Secrets copied into findings and reports (I) | Passive check evidence is shortened (300 chars) and cookie values are cut; findings stay in the project database; reports are exported only on request | ✅ M9 |
| T28 | Fuzzer payload lists shipping credentials (E) | Built-in lists are input-validation strings only; no username or password lists are shipped; custom lists come from the tester | ✅ M11 |
| T29 | OAST server abused as an open resolver or DNS amplifier (D) | Authoritative for one zone only, REFUSED elsewhere, no recursion; answers ≤ 32 bytes larger than the question (checked by the robustness harness); 20 queries per second per source, over-budget queries neither answered nor recorded | ✅ M18 |
| T30 | Interactions or the API token intercepted, or the self-hosted API used by others (I, S) | API over TLS with the server's own certificate pinned by SHA-256 in ChosProxy; 256-bit token compared in constant time; token and key files `0600` in a `0700` folder; token kept in `oast.toml` (`0600`) and never exported with settings | ✅ M18 |
| T31 | Hostile content in interactions (T, E) | The server never executes or reflects what it receives (fixed HTTP response); requests cut at 64 KiB with a 10 s read timeout and 256 connections per listener; interactions shown as text in the UI (T5) | ✅ M18 |
| T32 | One project's OAST data leaking into another (I) | Interactions stored only for identifiers created in that project; others counted and dropped | ✅ M18 |
| T33 | Local OAST server exposed on the network unintentionally (I) | Off by default; binds `127.0.0.1` unless a network address is chosen; the UI and the event log warn when it listens beyond loopback | ✅ M18 |
| T34 | Local processes controlling the lab browser through DevTools while the DOM Inspector runs (E, I) | DevTools only when the tester starts the DOM Inspector; loopback address and random port; port file inside the `0700` profile; closed with the browser; documented in docs/DOM_INSPECTOR.md and ADR-0027 | 🟡 M19 (accepted risk; `--remote-debugging-pipe` would remove it but needs file-descriptor passing) |
| T35 | Pages forging DOM Inspector reports (S, T) | The binding is removed from the page before page scripts run; reports parsed strictly with size limits, rate-limited, merged and shown as text; findings need the page response as evidence and say they are leads to confirm | ✅ M19 |
| T36 | Instrumentation changing the behaviour of the application under test (T) | Hooks call the originals with the same arguments; `eval` is not wrapped; nothing is injected through the proxy, and responses and CSP are not modified | ✅ M19 |
| T37 | Content discovery overloading or straying from the authorized target (D, E) | GET only; scope checked per URL (base origin while no scope exists) and refused when the base is out of scope; request cap, concurrency and rate limits; pause/cancel; only hits stored | ✅ M20 |
| T38 | Generated CSRF / clickjacking pages harming the tester (E) | PoC HTML is built with strict escaping in the UI, shown for review and copied; ChosProxy never serves, opens or executes it | ✅ M20 |
| T39 | Scheduled tasks running unattended beyond the authorization (D, E) | Schedules run only while the project is open; each run uses the normal start path (scope, limits, validation); minimum repeat 5 minutes; one-off schedules turn off; failures announced | ✅ M20 |
| T40 | Upstream proxy credentials leaking (I) | Stored only in `network.toml` with private permissions; never logged, audited or exported; password fields masked; Basic only over the proxy hop, as configured by the user | ✅ M21 |
| T41 | Invisible listener abused or looping (D, E) | Off by default, loopback by default like every listener; cannot be combined with proxy credentials; connections that land back on a listener are refused (508); TLS without a server name is refused; the ClientHello read is size- and time-limited | ✅ M21 |
| T42 | Match & Replace rules causing denial of service or silent tampering (D, R) | Rules validated on save, regex compiled size limited, bodies buffered only up to the hold limit; every changed message keeps its original in the history with a note naming the rules | ✅ M21 |
| T43 | Traffic sent somewhere unexpected through an upstream rule or host override (I, T) | Rules are explicit, ordered and shown in Settings → Network; each exchange sent through a proxy is noted in the history; overrides only apply to listed names | ✅ M21 |
| T44 | An imported CA key leaking or a wrong CA being used (I, S) | Key read once from the chosen file and stored like the generated one (private permissions, never exported or logged); refused unless CA, unexpired and matching; previous CA kept privately; import audited | ✅ M21b |
| T45 | Single-packet attacks overloading a target (D) | Manual, from a Repeater group the tester builds; at most 50 requests per send on one connection, sent once per click (no repetition or automation) | ✅ M21b |
| T46 | HTTP/2 clients exhausting the proxy's memory (D) | HTTP/2 to clients is off by default and per listener; at most 32 concurrent streams per connection, request bodies ≤ 8 MB, responses ≤ 64 MB, each read with timeouts; oversize messages fail with 413/502 | ✅ M21c |
| T47 | A script harming the machine or ChosProxy (E, D, I) | Rhai engine with no file, network, process or environment access; `eval` and modules disabled; operation, string, array, map, call and expression limits per run; scripts only see one message; failures and limits end the run with an error; only enabled, compiling scripts run | ✅ M22 |
| T48 | A shared script exfiltrating or tampering with traffic (T, I) | Scripts cannot send anything; rewrite scripts only change messages through explicit Match & Replace rules the tester adds; changed messages keep their original and a note naming the script | ✅ M22 |
| T49 | Imported scripts running before review (E, T) | Imported scripts are added switched off and never replace existing ones (ids get a suffix); files limited to 4 MB and validated; the same sandbox applies | ✅ M22b |
| T50 | A plugin abusing network.send (D, E) | Granted explicitly; Request Engine only (network settings apply); refused out of scope when a scope exists; 4 in flight and 300 per minute; every request stored with source plugin and the plugin named; its own traffic never fed back | ✅ M23 |
| T51 | A tampered or impersonated plugin (S, T) | Ed25519 signature over id, version and every file; changed files show "signature does not match" and need re-approval; trust is per key (fingerprints compared out of band); optional signed-only mode; signing never grants permissions; folder installs arrive disabled and never replace an installed plugin | ✅ M23 |
| T52 | Stored credentials leaking (I) | AES-256-GCM at rest with a random key, private files, write-only from the UI, never logged, audited or exported; tampering fails decryption; Debug output hides secrets | ✅ M24 |
| T53 | Session macros or platform auth sending credentials to the wrong host (I, S) | Platform credentials only for matching host patterns and only after a 401 challenge; macros replay the tester's own stored requests to their original targets; placeholders are filled only inside rules; macro requests recorded in the history | ✅ M24 |
| T54 | The browser crawl straying or acting on pages (D, E) | In scope (or the start origin), page limit, only navigation and link reading (no clicks or form submissions), loopback DevTools endpoint on a temporary profile closed afterwards | ✅ M24 |
| T55 | A scan flooding or straying from the target (D, E) | Only crawler requests (GET from links, in scope or start origin, words to avoid) unless the tester explicitly enables active audit; built-in configurations are passive-only and rate-limited; limits validated (requests, depth, items, per-point and total active probe budgets); each pattern audited once; active audit requires a non-empty project scope, in-scope start URLs and per-launch authorization confirmation (see T89). | ✅ M25/M13 |
| T56 | Secrets found in scripts spreading through findings and reports (I) | Evidence shows only the first and last characters and the length; the full value stays in the stored response the tester already has. |
| T57 | Suppression rules hiding real issues (R) | Rules apply only to automatic sources, never to manual findings; each has a type, host and path scope and a reason; adding and deleting is audited; rules are listed in the Findings view and marked findings keep their history. |
| T58 | A shared scan configuration doing harm on import (T, D) | JSON only, at most 1 MB, every limit validated, unique names, never started on import; built-ins cannot be overwritten. |
| T59 | A plugin silently rewriting, blocking or answering the tester's traffic (T, R, S) | Separate permission `proxy.intercept`, granted explicitly; hooks only while a scope is defined and only for in-scope requests; 2 s timeout and unusable answers fail open; every change, block and answer noted in the history entry, blocks and answers in the plugin log, hook registration audited; binary, oversized and WebSocket requests never shown. | ✅ M26 |
| T60 | Resource pools or live tasks overloading a target or the machine (D) | Pools only add limits on top of each task's own (validated: 1–200 in flight, ≤1000/s); back-off on 429/503 bounded to 60 s; live tasks only read stored traffic and never send; live crawl results capped (20 000 URLs), cross-request state bounded per origin. | ✅ M26 |
| T61 | A live task resuming unnoticed after reopening a project (R) | Only live tasks resume, in the state they had (running or paused); the task log says "Suspended…" and "Resumed after the project was opened"; they read traffic only. | ✅ M26 |
| T62 | A malicious or huge API definition (D, T) | Read from a file only; 10 MB, 5000 endpoints, depth and node limits, `$ref` cycles stop; remote references and imports never fetched; YAML through a safe-Rust parser; parsers in the robustness harness. |
| T63 | Sending an API definition's requests to hosts the tester may not test, or changing data (D, E) | Only hosts ticked by the tester, only in-scope URLs when a scope exists, read-only methods (and GraphQL queries) unless explicitly asked, rate limit and resource pool; every request in the history with its origin. |
| T64 | GraphQL introspection or schema data leaking credentials (I) | One introspection request, only on the tester's action and in scope; the original request's headers are reused for that endpoint only and stored in the project like any Repeater send. |
| T65 | Another program or a web page driving ChosProxy through the automation API (S, E) | Off by default; 127.0.0.1 only and non-loopback peers dropped; 256-bit token in a private file, constant-time comparison; requests with `Origin` refused and `Host` must be the loopback listener (no CSRF, no DNS rebinding); body cap; same engine checks as the UI (scope, safe defaults); changes audited. Residual: local code running as the user can read the token, as it can read projects. |
| T66 | Headless runs leaving a listener or API open unnoticed (E, R) | `serve` prints the API address, the listeners and the token file first, binds loopback, and stops on Ctrl-C (closing the project); the API is opt-in per process. |
| T67 | Traffic, credentials or client data leaking to an AI provider (I) | Off by default; local mode is loopback-only; only attached items, never the project; redaction of auth headers, cookies, JWTs, secret parameters and fields, known key formats and custom patterns; size limit; external calls refused unless they carry the digest of the previewed context; keys in the keyring; no telemetry; audit log without content. |
| T68 | A model's answer misleading the tester or steering actions (T, E) | ChosAI only returns text and has no tools (no sends, no project changes); answers are marked as model output; suggestions are manual steps; ChosAgent (M30) acts only through engine-enforced permissions (T70). |
| T69 | Prompt injection from captured traffic (T) | Traffic is data in the user message, the system prompt is fixed, and the model cannot act; the worst case is a wrong or manipulated explanation, mitigated by T68. |
| T70 | An agent acting beyond what the tester wants: sending traffic, changing the project, reaching the OS (E, T) | A fixed tool catalog with no shell, file or OS access; unknown tool names refused; DENY/ASK/ALLOW enforced by one engine dispatcher with per-tool caps (a hand-edited `agent.toml` cannot lift them); `send_request` is always ASK with the exact request shown, needs a defined scope containing the target (checked before asking and before sending), and has a per-task budget and a step limit; findings are drafted as tentative; session rules are asked; approvals are UI-only (not in the automation API); everything is recorded in the AI activity log. |
| T71 | Prompt injection through traffic steering the agent (T, E) | Tool results are data in tool messages; the model can only request catalog tools, and anything that sends or changes the project waits for the tester (by default; sending always); an injected request is shown in full before it could be sent, only in scope; the agent cannot raise its own permissions. |
| T72 | Agent activity leaking data to an external model (I) | Every external model call waits for the tester's approval of the exact new context (digest checked); tool results are redacted with the ChosAI rules and cut to the context limit; local models keep everything on the machine. |
| T73 | A project file read by someone who gets the disk, a backup or a copy (I) | Optional SQLCipher encryption of the file, its WAL, its backups and its copies; encrypted temporary projects; plain copies only when chosen explicitly; files private (0600). |
| T74 | Project passwords leaking (I) | The key exists only in memory (`ProjectKey`, hidden in debug output), never stored, logged, audited, returned to the UI or put in URLs; the CLI reads it from the environment or a file, never from arguments; the API takes it in the body over loopback with the token. |
| T75 | A lost password (A) | Stated before encrypting and in the Project view: the file cannot be opened without it; there is no recovery or back door by design. |
| T76 | A cleanup deleting the wrong file (T, A) | Only names ChosProxy creates, inside its own temporary directory; the open project and the running browser profile protected; other runs' files only on request after a day without changes; links never followed or removed; a test with decoy files. |
| T77 | The API's event stream used to watch a tester's work, or to stall the engine (I, D) | Same token, `Origin` and `Host` checks as every route, loopback only; at most 8 streams; a bounded queue per client and a client that does not read is dropped; streams end with the server. |
| T78 | A plugin rewriting or hiding responses (T, I) | The same explicit permission as request hooks, only in-scope traffic with a scope defined, 2 s then fail open, every change and block noted in the history with the original kept. |
| T79 | A listener presenting an unexpected certificate (S) | The certificate is the tester's explicit choice per listener; a certificate that cannot be loaded stops the listener instead of falling back; a chosen key must match its certificate. |
| T80 | NTLM credentials sent to the wrong server or downgraded (I, S) | Only for hosts with an NTLM rule, only after that host's `401 NTLM` offer; NTLMv2 only (never LM or NTLMv1); the stored request shows what was sent. |
| T81 | The keyring key exposed, or the keyring lost (I, D) | Key in a private file, the OS keychain or derived from a master password that is never stored (PBKDF2, 600 000 rounds); a locked keyring is neither read nor overwritten; a lost keychain item or password is said plainly to lose the credentials. |
| T82 | The SMTP sink used as an open relay or filled with mail (E, D) | It never relays or delivers; no AUTH or STARTTLS; bounded commands, recipients, size and connections; off by default; only mail that carries an identifier of the project is kept. |
| T83 | A WebSocket script breaking or leaking a session (T, D) | Scripts run in the same sandbox and limits as other rewrite scripts, only through a rule the tester adds; a failing script leaves the message unchanged. |
| T84 | A Fuzzer CSV export running a formula when opened in a spreadsheet (T, E) | Values starting with `=`, `+`, `-`, `@`, tab or carriage return are prefixed with `'`; fields are quoted; the file is written only where the tester chooses. | ✅ M33 |
| T85 | The event log file read by another user, or growing without end (I, D) | Private file (`0600`) in the private log directory; compacted to the last 2,000 entries at start; Clear empties it; it holds only the event log's own text (notices and errors), never request or response contents. | ✅ M33 |
| T86 | Crash recovery stealing a live sibling instance's project, leaking secrets in session markers, or re-sending interrupted traffic (T, I, D) | Session markers live per instance (`sessions/<session_id>.json`, `0600`), store only path/encryption/PID/start-time/task metadata (never keys, passwords, tokens or bodies), and verify PID + process start time via `sysinfo` so live sibling processes are never claimed; restore runs `PRAGMA quick_check`, marks interrupted traffic-sending tasks as `Cancelled` (never auto-restarting sends), and protects recoverable temp files from automatic cleanup; read-only mode (`ensure_writable`) blocks all mutations when inspecting a recovered or read-only project. | ✅ M31 |
| T87 | A failed or tampered Organizer/settings export corrupting existing files or importing partial data (T, D) | Exports write to a sibling `.tmp` file (`0600`) and rename atomically so a failed export never truncates an existing destination; sealed files use PBKDF2-HMAC-SHA256 (600 000 rounds) + AES-256-GCM with an authenticated header (`kind`, version, salt, nonce) and are imported all-or-nothing inside a single transaction. | ✅ M31 |
| T88 | Security Center or audit log queries exposing private keys, passwords or tokens (I) | `security_overview()` is strictly local (no network I/O) and inspects only configuration metadata and file presence/permissions — never returning CA private keys, listener passwords, Automation API tokens, OAST tokens, keyring secrets or project keys; audit log entries record action names and non-secret summaries only. | ✅ M31 |
| T89 | Active audit running unintentionally, probing out-of-scope hosts, or altering target state (E, T, D) | Off by default in all built-in configurations; `active_authorized` is stripped when saving or importing scan configs so every active launch requires fresh confirmation; engine and scheduler enforce non-empty project scope, in-scope start URLs, per-point (`1..=50`) and total (`1..=10 000`) probe budgets, concurrency (`1..=32`) and rate (`1..=100` req/s) limits; non-idempotent methods (`POST`, `PUT`, `PATCH`, `DELETE`) are skipped unless `active_allow_unsafe_methods` is explicitly enabled; scope is revalidated before every probe; redirects are inspected via `Location` without following; SQLi checks use non-destructive boolean/syntax differentials only; reflected XSS is reported as `Tentative` when not executed in a browser. | ✅ M13 |
| T90 | Custom active check scripts sending unbounded probes or bypassing scope (D, E) | Active check scripts (`fn active_probes` + `fn active_check`) run inside the same Rhai sandbox (T47), return at most 16 probe strings per insertion point, and share the scan's per-point and total active request budgets, rate limiter, Resource Pool, Session Rules, and per-probe scope revalidation. | ✅ M13 |
| T17 | Lab browser running as root disables Chromium sandbox (E) | Warned in the UI when `--no-sandbox` is required; recommendation to run as a normal user | ✅ M2 |
